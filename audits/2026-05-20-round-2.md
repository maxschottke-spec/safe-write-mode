# Security-Audit safe-write-mode — Post-Fix-Verifikation

**Datum:** 2026-05-20
**Scope:** Repo-State nach Pull `e8e23f8..1150e7d` (8 Dateien, +520 LOC, neuer `test/audit-fixes.test.js`)
**Methodik:** /harden-Skill, 5 Domain-Subagenten (Auth/AuthZ, Injection/Input, Secrets/Crypto, Dependencies, Config) + Tool-Pass mit gitleaks v8.30.1, trivy v0.70.0, semgrep v1.162.0
**Verdict:** **NICHT WASSERDICHT** — 2 CRITICAL Chains, 10 HIGH, 10 MEDIUM, 8 LOW

## TL;DR

Die Fixes funktionieren auf der Oberfläche (env-tamper M3, body-non-enumerable N8, expires_in-Validierung N2). Alle drei Standard-Scanner (gitleaks, trivy, semgrep mit 91 Rules) finden null Befunde — die Library ist sauber gegen klassische OWASP-Patterns.

**Aber:** Das Sicherheitsdesign hat Lücken, die nur eine kontextuelle Analyse findet. Drei voneinander unabhängige Bypässe der "three-key write protection" existieren gleichzeitig, und eine vollständige Credential-Exfil-Kette ist komponierbar. Solange diese nicht zu sind, ist das Marketing-Versprechen ("every write refused before it leaves the process") nicht gedeckt.

## CRITICAL — Chains

### CHAIN-1: Guardrail-Promise broken (drei unabhängige Bypässe)

Die README garantiert die Three-Key-Write-Protection. Im Code existieren **drei voneinander unabhängige Wege** dieses Versprechen zu brechen:

**(a) Self-Attestation** — `src/safety.js:90-131`

```js
const { confirmed = false, destructive = false, reason = null } = opts;
```

`opts` kommt vom Caller. Ein Agent ruft schlicht
`client.write.delete('/x', { confirmed: true, destructive: true, reason: 'ok' })` —
es gibt keinen separaten Host-Channel der bestätigt dass ein Mensch die Bestätigung gegeben hat.

**Fix:** Confirmed/destructive aus einem signierten Confirmation-Token verifizieren, das eine Host-Komponente (nicht der Agent) ausstellt.

**(b) Exported Capability Symbol** — `src/index.js:16`, `src/integrationFactory.js:5`

```js
const __INTERNAL_WRITE__ = Symbol('safeWrite.internalOp');
module.exports = { ... __INTERNAL_WRITE__, ... };

function createIntegration({ name, client, readOnly = false }) { ... } // kein client-check
```

Jeder Importeur kann einen fake-client mit eigener `[__INTERNAL_WRITE__]`-Methode bauen und durch `createIntegration` schleusen — OAuth/Bearer-Logik komplett umgangen.

**Fix:** Symbol nicht exportieren. Stattdessen WeakSet von validated-clients in `integrationFactory`, das nur Adapter aus diesem Package akzeptiert.

**(c) GraphQL Mutation-Smuggling** — `adapters/graphql.example.js:12-43`

```js
function isMutation(query) {
  const trimmed = String(query).trim().replace(/^#[^\n]*\n/gm, '');
  return /^mutation\b/i.test(trimmed);
}
```

- `﻿mutation { ... }` (BOM-Prefix) bypasst `trim()` partiell
- `query Foo { x } mutation Bar { delete }` mit `operationName: "Bar"` matcht den Regex nicht → läuft durch `client.get()` ohne Gate
- NBSP/Unicode-Whitespace ähnlich umgehbar

**Fix:** GraphQL-Dokument mit `graphql-js` `parse()` analysieren und prüfen ob *irgendeine* `definitions[*].operation === 'mutation'`. Mixed-operation grundsätzlich refusen.

### CHAIN-2: Credential-Exfil (vier kompositionsfähige Lücken)

Die folgenden vier Lücken ergeben zusammen einen vollständigen Bearer-/OAuth-Token-Exfil-Vektor:

**(a) SSRF — `src/http.js:67-85`**

`request()` fetcht beliebige URLs. Keine Scheme-Allowlist (HTTPS-only), keine RFC1918/127.0.0.0/8/169.254.0.0/16/::1-Blocklist, keine DNS-Rebind-Defense. AWS-Metadata-Endpoint `169.254.169.254` ist erreichbar.

**(b) Path-Injection in Adaptern — `adapters/rest-oauth.example.js:63`, `adapters/rest-bearer.example.js:27`**

```js
url: `${baseUrl}${path}`,
headers: { Authorization: `Bearer ${accessToken}` }
```

Wenn `path` als absolute URL (`https://evil.tld/exfil`), Protocol-relative (`//evil.tld/x`), Backslash, oder `@`-userinfo-Trick übergeben wird, geht der Bearer-Token zu beliebigem Origin. Das ist Pattern-mäßig der kanonische "Bearer-Leak via Path-Injection" — und es ist in den *empfohlenen Example-Adaptern* drin, also kopieren Adopter das ungeprüft.

**Fix:** `path` muss mit `/` starten, kein `://`, kein leading `//`, kein `\`, kein `@` vor erstem `/`. Sauberer:

```js
const target = new URL(path, baseUrl);
if (target.origin !== new URL(baseUrl).origin) throw new Error('cross-origin path refused');
```

**(c) Logger no-redact — `src/logger.js:12-28`**

```js
const entry = { ts, level, msg, ...(meta || {}) };
process.stderr.write(JSON.stringify(entry) + '\n');
```

Spread vom Caller-`meta` ohne Filter. Wenn irgendwer `logger.error('refresh failed', { headers })` aufruft, landen Bearer/Set-Cookie verbatim in stderr **und** im NDJSON-Audit-Log, das in `docs/audit-trail.md:67` explizit als S3/SIEM-shippable beworben wird.

**Fix:** Rekursiver Redactor in `logger.js`, Regex

```
/^(authorization|cookie|set-cookie|password|secret|token|api[_-]?key|client[_-]?secret|refresh[_-]?token|access[_-]?token)$/i
```

Werte mit `"[REDACTED]"` ersetzen vor `JSON.stringify` in beiden Pfaden (consoleLog + logWrite).

**(d) Error-Message URL-Leak — `src/http.js:90,101` → `src/safety.js:226,232`**

```js
// http.js:101
throw new HttpError(`HTTP ${res.status} ${res.statusText} for ${method} ${url}`, ...);
// safety.js:226
logger.logWrite({ ..., outcome:'error', error: err.message, status: err.status ?? null });
```

Full URL inkl. Query-Strings landet in `err.message`. URLs mit `?api_key=...`, `?token=...`, presigned-S3-URLs etc. werden verbatim in NDJSON-Audit-Log und stderr geschrieben. Macht den N8-Aufwand (body/headers non-enumerable) zunichte.

**Fix:** Query-String aus URL strippen vor Interpolation; Substring-Filter für `Bearer\s+\S+`, `sk-\S+`, `ghp_\S+`. Oder URL durch Identity-Hash ersetzen für Logging.

## HIGH

### H1 — AUTH-MODE-ENV-TAMPER

**File:** `src/safety.js:19-32`
**Befund:** Kill-Switch nur aus `process.env.SAFE_WRITE_MODE` (+ `MODE`-Fallback). In-Process-Tool kann den Wert mutieren.

```js
let raw = process.env.SAFE_WRITE_MODE;
if (raw == null || raw === '') {
  if (process.env.MODE != null && process.env.MODE !== '') { ... raw = process.env.MODE; }
}
```

Beliebiges Plugin oder Tool das `process.env.MODE = 'read-write'` setzt, deaktiviert den Schutz prozessweit. M3-Fix mildert nur die Kollision, nicht das Tampering selbst.

**Fix:** Mode beim Init in frozen Closure einsperren (`Object.freeze`). MODE-Fallback in v0.2 hart entfernen. `lockMode()`-API anbieten, die weitere Änderungen ignoriert.

### H2 — DEP-NODE-EOL

**File:** `package.json:34-36`
**Befund:** `"node": ">=18"` — Node 18 ist seit April 2025 EOL, erhält keine Security-Patches mehr (heute 2026-05-20).
**Konsequenz:** Security-Library erlaubt explizit unsupported Runtime; widerspricht der SECURITY.md-Selbsteinschätzung.
**Fix:** `"node": ">=20.18"` (aktive LTS), README begründen.

### H3 — CFG-PUBLISHER-UNVERIFIED

**File:** `package.json:32, 37-44`
**Befund:** `author`, `repository.url`, `bugs.url`, `homepage` alle leer.

```json
"author": "",
"repository": { "type": "git", "url": "" },
"bugs": { "url": "" },
"homepage": ""
```

**Konsequenz:** Konsument von `npm install safe-write-mode` kann Publisher-Identität nicht verifizieren. SECURITY.md verweist auf "the maintainer (see repository metadata)" — Metadaten leer → Disclosure-Kanal kaputt.

**Fix:** Vor `npm publish` konkrete `author` + `repository.url` + `bugs.url` + `homepage` setzen. Idealerweise `npm publish --provenance` aus signiertem GitHub-Actions-Workflow.

## Discovery Candidates (neue Patterns)

**SWM-INTERNAL-SYMBOL-EXPORT** (HIGH, D1)
"Internal capability tokens MUST NOT be exported from a security boundary."
Library exportiert ein Capability-Symbol als public API. Generisches Pattern für Security-Libraries die Symbol-basierte interne Marker verwenden.

**INJ-AUDIT-PRE-HASH-DOS** (LOW-MEDIUM, D2)
`src/safety.js:42` — `canonicalStringify` rekursiv ohne Cycle-Detection und ohne Depth-Cap. Caller-supplied body mit circular ref oder Deep-Nesting blowt den Stack vor dem `outcome: pending`-Audit-Log → silent audit-suppression. Komponiert mit M4 (Path-Traversal-Logfile) zu Audit-Integrity-Defeat.
